# 04 — Architecture

## 4.1 Stack

| Layer | Choice | Why |
| --- | --- | --- |
| Framework | Next.js 15.5 (App Router), React 19 | Server rendering for SEO and first paint; file-based routing; built-in image optimisation |
| Language | TypeScript, strict | Content shapes are typed at the boundary between JSON and pages |
| Styling | Tailwind CSS v4 with a token layer in `globals.css` | One design vocabulary; no component library to fight |
| Icons | `lucide-react` | Small, tree-shaken, consistent stroke weight |
| Validation | `zod` | Same schema vocabulary on the server as in the editor |
| Fonts | `Inter` + `Source Serif 4` via `next/font/google` | Self-hosted at build time — no third-party font request, no layout shift |
| Persistence | JSON files under `/content`, line-delimited JSON under `/data/submissions` | The corpus is a dozen articles, not a database; files are diffable and back up with `cp` |

No UI framework (no Bootstrap/MUI/shadcn). No client-side data fetching. No analytics or third-party scripts, so there is nothing to consent to and nothing to slow the page down.

## 4.2 Rendering strategy

- **Static (○)** — home, services, about, membership, contact, faq, partners, news index, projects index.
- **Static with params (●)** — service, project, article and category detail pages, generated by `generateStaticParams` at build time.
- **Dynamic (ƒ)** — `/admin/**` (session-dependent, `no-store`), `/api/enquiry`, `/api/newsletter`.
- **Generated** — `/sitemap.xml`, `/robots.txt`, `/icon.svg`.

Publishing from the console writes the JSON file and calls `revalidatePath` on the affected routes, so a saved article is live on the next request without a rebuild.

## 4.4 Content layer

`src/lib/content.ts` exposes `getArticles`, `getArticle`, `getNewsCategories`, `getProjects`, `getProject`. Pages never touch the file system. Reads are wrapped in `try/catch` with a safe fallback so a malformed JSON file degrades one section instead of taking down the site; the admin write path writes to a temporary file and renames it, so a failed write cannot truncate the store.

Types (`Article`, `Project`) are declared once in `lib/content.ts` and reused by the editor, the renderer and the write layer.

## 4.5 Component model

Server components by default. Client components are limited to four, each with a stated reason:

| Component | Client because |
| --- | --- |
| `Reveal` | IntersectionObserver for the entrance transition |
| `Header` | Mobile menu state, scroll state, route-change close |
| `EnquiryForm`, `NewsletterForm` | Local validation state, fetch, success/error messaging |
| `LoginForm`, `ConfirmSubmit` | `useActionState`, `window.confirm` |

## 4.6 Image strategy

`next/image` with AVIF/WebP conversion, explicit `sizes`, and a curated `deviceSizes` set (360–1920). Hero photography is prioritised on the homepage only; everything below the fold is lazy. Society logos render at their intrinsic aspect ratio inside a fixed-height box, so the brand mark is never stretched.

## 4.7 Failure behaviour

| Failure | Behaviour |
| --- | --- |
| `content/news.json` unreadable | News section renders empty; the rest of the site is unaffected |
| Submission write fails (read-only disk) | API returns 500 with a message pointing to the telephone numbers; nothing is silently dropped |
| Admin credentials unset | Console shows a configuration notice and refuses to authenticate |
| Unknown URL | Branded `not-found` page with recovery links |
